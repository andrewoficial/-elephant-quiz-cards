# ТЗ: QuizCards (рабочее название)
Приложение для заучивания карточек. Предметная область MVP: Java, вопросы для собеседования.
Кроссплатформа: Windows, Android, iOS (iOS позже, требуется Mac).

## 1. Стек и инструменты

- Kotlin Multiplatform + Compose Multiplatform (shared-модуль: domain, data, UI).
- БД: SQLDelight (или Room KMP). DI: Koin. Сеть: Ktor Client.
- Среда разработки: IntelliJ IDEA (основная), Android Studio — для Profiler/Layout Inspector при необходимости. Проект IDE-независим (Gradle — источник истины).
- Десктоп-итерации: Compose Hot Reload.
- Синхронизация: Google Drive (REST, все платформы), GitHub (публикация колод).
- Токен DeepSeek: хранить в зашифрованном виде (Keystore/Keychain), позже — прокси-сервер.

## 2. Сущности

### 2.1 Дерево тем (5 уровней)
Уровень 0: Дисциплина → 1: Область → 2: Тема → 3: Раздел → 4: Секция.

```
TopicNode(id, parentId?, level: NodeLevel, name, order, color?,
          createdAt, updatedAt, deletedAt?, syncVersion)
```
- Одна таблица-дерево. parentId == null только у DISCIPLINE. Родитель обязан иметь level-1 (контроль в репозитории).
- Полный путь в карточке НЕ хранится — только topicId. Путь вычисляется по parentId.

### 2.2 Карточка
```
Card(id: UUID, schemaVersion, syncVersion,
     createdAt, updatedAt, deletedAt?,            // soft delete для синка
     type: SELF_CHECK | MULTIPLE_CHOICE,
     question: String,           // Markdown
     questionCode: String?,      // код в вопросе (отдельное поле)
     answer: String,             // Markdown
     answerCode: String?,
     explanation: String?,
     options: [CardOption(id, text, isCorrect, order)],
     variants: [QuestionVariant(id, questionText, questionCode?)],  // ≥1
     topicId: String,            // узел уровня 2..4
     labels: [String], tags: [String],
     source: MANUAL | AI_GENERATED | IMPORTED,
     aiUnreviewed: Boolean,      // ИИ-карточка без ручной проверки (бейдж)
     favorite: Boolean, difficulty: Int?,   // 1..5 или null
     // SM-2 (на уровне карточки, худший вариант правит срок):
     easinessFactor: Double,     // старт 2.5
     intervalDays: Int, repetitions: Int, dueDate: Long,
     lastReviewedAt: Long?, lapses: Int)
```

### 2.3 Журнал повторений (append-only, синхронизируется целиком)
```
ReviewLog(id: UUID, cardId, variantId, reviewedAt,
          mode: CHOICE | TYPING | OPEN | SELF_CONTROL,
          quality: Int,           // 1 = провал, 3 = успех с потерями, 5 = чистый
          livesLost: Int?,        // для TYPING
          intervalBefore, intervalAfter, timeSpentMs?)
```

### 2.4 Состояние карточки (пользовательское, в progress-файле)
state: NEW | LEARNING | REVIEW | ARCHIVED | SUSPENDED (отложенные)
+ все SM-2 поля. Текущее состояние = быстрый снимок; полная история восстанавливается проигрышем ReviewLog.

## 3. Методы зубрёжки («Джунгли»)

| Метод | Правила |
|---|---|
| Варианты ответа (CHOICE) | Выбор из options. Оценка: всё-или-ничего (при нескольких верных — все верные и только они). |
| Ввод по буквам (TYPING) | Только для коротких ответов (без кода). Проверка каждой буквы; неверная буква = −1 жизнь; 3 жизни на ответ. UI в духе Lingualeo: буквы на «разорванных бумажках». Код-ответы: метод недоступен. |
| Открытый вопрос (OPEN) | Свободный ввод + кнопка «Проверить». Сравнение через адаптер нормализации (регистр/пробелы). Формат ответа — требование в тексте вопроса; не справился — ошибка. |
| Самоконтроль (SELF_CONTROL) | Переворот карточки, кнопки «помню / не помню». |

- Каждый показ — случайный вариант из variants (если >1).
- SM-2: провал → quality 1; успех с потерями → 3; чистый → 5.
- Применимость: CHOICE — только MULTIPLE_CHOICE-карточки; TYPING — только короткие ответы без кода; OPEN, SELF_CONTROL — все.
- Ответы с кодом: компиляция+тесты или ИИ-судья — POST-MVP, отдельная фича.

## 4. Критерий «выучено»

Карточка выучена, если:
1. для КАЖДОГО варианта последний ответ в КАЖДОЙ применимой форме — верный, И
2. intervalDays ≥ 20.

Прогресс узла дерева = выученные карточки поддерева; агрегируется рекурсивно вверх (процент по секциям → разделам → темам → областям → дисциплинам).

## 5. Синхронизация и обмен

### 5.1 Структура на Google Drive
```
/QuizCards/
  decks/deck-{uuid}.json        — контент колоды
  decks/deck-{uuid}.media/      — медиа (зарезервировано)
  progress/progress-{userId}.json — состояние пользователя + полный ReviewLog
```
GitHub: публикация только decks/.

### 5.2 deck-{uuid}.json
formatVersion, deckId, name, updatedAt, topics[] (поддерево с полным путём узлов), cards[] (контент без SM-2/прогресса).

### 5.3 progress-{userId}.json
formatVersion, userId, updatedAt,
cards: { cardId → { state, SM-2 поля, variants mastery (последний результат по каждому варианту/форме) } },
reviewLog: [ReviewLog, ...]  // append-only

### 5.4 Разрешение конфликтов
- Контент колоды: per-card syncVersion (больше побеждает), tie → поздний updatedAt.
- Состояние карточки: last-write-wins по каждой записи отдельно.
- ReviewLog: объединение по id (append-only — конфликтов нет).
- Откат на произвольный день: проигрыш ReviewLog до точки.

### 5.5 Импорт колоды (правило слияния с деревом)
1. Узел с таким UUID → присоединить к существующему.
2. UUID новый, но совпадают level+name → спросить пользователя.
3. Иначе → создать новый узел.
4. Карточка с известным UUID: syncVersion новее → обновить; иначе пропустить. Новый UUID → добавить.

## 6. Экраны (навигация)

| Маршрут | Экран |
|---|---|
| subjects | Главный: аккордеон дисциплин → области с прогресс-барами |
| jungle/{areaId} | «Джунгли»: 4 метода + очередь на сегодня |
| training/{areaId}/{mode} | Зубрёжка (один экран, параметр mode) |
| editor/{areaId} | Карточки: список/правка, поиск, импорт (3 вкладки) |
| settings | Настройки: токен ИИ, тема, синхронизация, экспорт |
| free_training | Произвольная тренировка (фильтры: теги, «часто ошибаю», «давно не повторял») |
| interview | Режим собеседования: N случайных вопросов подряд, итоговая оценка |
| ai_chat | Чат с ИИ (зарезервирован) |

- «Часто ошибочные» и «давно не повторённые» — фильтры внутри free_training, не отдельные экраны.
- Пустая очередь: редирект-предложение в free_training.

## 7. DeepSeek (МVP-объём)

Два навыка: (1) предложить варианты ответа по вопросу, (2) придумать похожую карточку.
Ответ — JSON (формат подберётся на месте). Промпт — за пределами ТЗ.
Сгенерированные карточки не блокируются ручной проверкой; помечаются aiUnreviewed (бейдж, фильтр).

## 8. MVP-разрез

Включает: дерево тем, карточки, 4 метода, SM-2, критерий выучено, статистика по дереву,
редактор + поиск, импорт/экспорт JSON, демо-колода Java, Drive-синк.

Позже: GitHub-публикация, DeepSeek, чат с ИИ, режим собеседования, медиа, уведомления,
код-ответы (компиляция/ИИ-судья), iOS.

## 9. Журнал решений (фиксация спорных моментов)

1. Колода = ветка дерева + карточки, экспортируется с полным путём узлов. Слияние при импорте — по §5.5.
2. «Ввод по буквам» — только короткие ответы; для кода недоступен.
3. OPEN = ввод + кнопка «Проверить»; TYPING = посимвольно, 3 жизни; SELF_CONTROL = «помню/не помню».
4. Матрица применимости форм по типам карточек — по §3; формат ответа закрепляется в тексте вопроса.
5. Множественный выбор: всё-или-ничего.
6. ReviewLog синхронизируется целиком (append-only, объединение по id). Откат = проигрыш лога.
7. Пустая очередь → предложение free_training.
8. ИИ-карточки без обязательной проверки; флаг aiUnreviewed. Уведомления — out of scope.
